# Screen review and Chessbook comparison — 6 October 2026

## Scope and evidence

Reviewed the main navigation, Today, opening home, repertoire builder/analysis,
line browser/editor, continuous recall/guided practice, import/source update,
game inbox/review, Progress and the five thinking drills. Evidence combines source
inspection, disposable local UI journeys and desktop/iPhone-size browser tests.
Test engine responses are fixtures; this is a usability review, not a fresh
validation of chess-analysis accuracy or learning effectiveness.

Chessbook's public guest dashboard, repertoire page and building page were
inspected directly. Its authenticated, paid and native-app workflows were not
audited. Feature claims are drawn from its
[official app listing](https://apps.apple.com/us/app/chessbook-master-openings/id6466343415).
The observable web workspace is at [Chessbook](https://chessbook.com/).
No account, copied content or external repertoire was changed during comparison.

## Improvements implemented in 1.5.13

| Screen | Problem | Change |
| --- | --- | --- |
| Navigation | Browser Back did not restore top-level navigation; active tabs relied on colour | History-aware navigation, current-page semantics, keyboard skip link |
| Today | Full progress dashboard and large empty spacing preceded the board | Compact practice summary; detailed priorities remain in Progress; smaller heading/board spacing |
| Progress | Empty sessions were offered; loading failures could produce a blank screen | Import-first action for empty/no-profile installations, visible loading/error/retry, guarded profile/session requests |
| My games | Optional sync setup preceded the advertised paste field | PGN first; optional Lichess disclosure below; connected users retain accessible sync controls |
| PGN preview | Edited PGN could retain the previous game's player selector | Editing invalidates preview and selected player; editing is disabled during analysis/import |
| Game library | Every game was rendered before the review | Search across all returned games; bounded list with Show more; selected game remains accessible |
| Game review | Context links scrolled to the inbox; obsolete requests could replace the selected game | Specific-game links scroll to the selected review; prior requests are cancelled; loading/retry visible |
| Review feedback | Classification forms competed with the learning explanation | Optional classification editor collapsed; explanation component reused; missing reasons do not masquerade as chess advice |
| All thinking drills | First-load failure could hide the error because no exercise existed | Shared loading/error/retry panel, plus a PGN route when there are no positions |
| Repertoire import | Successful persistence followed by a failed refresh appeared to be an import failure | Success and refresh warning separated; cleared submission prevents accidental reimport |
| Shared controls / boards | Raw inputs, small targets, small mobile text, desktop boards taller than the screen and sticky mode controls covering questions | Dark input styling, 44px non-board control heights, 16px mobile fields, larger coordinates, viewport-aware thinking boards, non-overlapping mode controls and reduced-motion support |

The change adds no cloud dependency, database migration or new opening content.
Builder drafts, path-specific notes, shared recall cards, source-update previews
and continuous line practice remain intact.

## Comparison after this pass

| Area | Thinking Board | Chessbook benchmark / remaining gap |
| --- | --- | --- |
| Basic recall | Correct moves advance; mistakes allow another attempt; hints/explanations are requested | Validate the feel on real phones and with uncoached users, not just test success |
| Workspace consistency | Board-first editor, separate investigation board, retained line cursor | Chessbook's observed board/sidebar stays more visually stable across tasks; ours still has separate layouts |
| Practical preparation | Rating-band replies, explicit rarity/uncertainty, own-game evidence and opt-in coverage | Chessbook advertises probability-driven coverage and suggestions. Our next-action guidance still needs to feel less like a collection of controls |
| Study organisation | Named chapters/variations, path notes/marks, import/update/export and shared memory | Large studies need chapter-level progressive disclosure and measured performance; small-study tests do not establish large-study quality |
| Game feedback | Lichess import and pasted PGNs use the same matcher; return to the specific game | Validate discoverability of recall miss versus opponent surprise versus weak chess move |
| Understanding | Editable reasons, source/personal separation and SEE → CANDIDATES → CHECK | Opportunity to exceed memorisation: train the reason and the consequence of a changed position, without inventing explanations |
| Mobile polish | Touch board, tap/drag tests, bigger fields and targets | Native-app polish and physical iPhone gesture testing remain an unproven gap |
| Middlegame material | Quiet-plan and blunder-check drills from games | Chessbook advertises model games. Not a current priority for this user; focus on existing learning quality |
| Privacy / ownership | Docker, local engine, SQLite, private imports, backups and PGN portability | A concrete differentiator, not proof of superior opening training |

Chessbook remains the benchmark for cohesion and low-friction preparation.
Passing functional tests is not evidence that this product matches its overall
quality or produces better retention.

## Next work, in order

1. **Measure novice/mobile friction.** Ask an uncoached learner to import a study,
   find a variation, recover a wrong move, edit a note and review a pasted game.
   Record extra clicks, lost context and requests for help. Test physical iPhone
   drag, tap, promotion and scrolling separately. Fix observed friction first.
2. **Unify the workspace further.** Keep board dimensions, selected position,
   breadcrumbs and one primary action consistent across Browse, Edit and Practice.
   Protect unsaved comment edits across top-level navigation, not just within a line.
   Move uncommon management controls away from the learning path. Do not restore
   a non-functional home board merely to imitate Chessbook's appearance.
3. **Make large studies easy.** Test hundreds of chapters/paths, collapse chapters,
   preserve expanded sections/search and highlight the exact shared-move split.
   Add rendering optimisation only where measurements justify it.
4. **Strengthen real-game transfer.** Show whether a remembered move was actually
   used in later games; keep sample sizes and opponent deviations separate. Compare
   unaided seven-day recall and subsequent repertoire adherence, not raw streaks.
5. **Improve understanding, not automatic prose.** Help write central idea,
   opponent threat and next plan; add optional contrast questions for similar
   branches. Any generated chess explanation needs engine/position checks and a
   clear provenance label. Do not interrupt normal recall with compulsory quizzes.

Chess.com sync, social features, expanded built-in lines and model-game libraries
are deliberately not part of this priority list.

## Regression / usability gates

Run `npm run check` and `npm run test:e2e` on disposable test databases. New UI
regressions cover history/keyboard access, fresh-install Progress, paste-before-sync,
preview invalidation, first-load retries in all modes, game search/request races,
and successful import with failed refresh. Existing tests cover square geometry,
touch input, uninterrupted recall, hints, notes and source-update fidelity.

Use [the human usability protocol](OPENING_USABILITY_CHECKS.md) before claiming
Chessbook parity. No physical-phone or delayed-recall outcome is claimed here.
