# Project guidance

Read [the project charter](docs/PROJECT_CHARTER.md) before proposing or implementing
improvements. It governs priorities; historical reviews and competitor comparisons
are supporting evidence.

For every improvement, record the charter's purpose check in the proposal or change
description: learner need and requirement ID, existing capability/simplest option,
expected benefit, acceptance evidence, costs/protections and decision. Scale detail
to the change and recheck the result before delivery. Test counts, feature parity
and exercise completion do not prove learning benefit.

Preserve games, repertoires and training history. Distinguish planned requirements
from shipped behaviour. Respect the user's current implementation scope: a charter
or roadmap does not itself authorise application changes.
